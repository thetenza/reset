# RESET — магазин цифровых товаров (MVP маркетплейса)

Витрина с разделами, поиском и неограниченным числом товаров; покупка через Digiseller — по ТЗ «RESET — собственный магазин четырёх товаров».
Node.js 22 + Express, SQLite (встроенный `node:sqlite`), страницы рендерятся на сервере.

## Запуск

```bash
npm install
cp .env.example .env   # заполнить
npm start              # http://localhost:3000
npm test               # проверки ТЗ на моках Digiseller
```

Пока `DIGISELLER_SELLER_ID` пуст, сайт работает в **демо-режиме**: помеченные демо-товары, покупка отключена, индексация закрыта.
Без SMTP коды входа в dev выводятся в консоль.

## Подключение реальных товаров
1. Заполнить `.env` (Digiseller, SMTP, поддержка, `ADMIN_EMAILS`).
2. Войти на `/login` под email админа → `/admin`.
3. Для каждого из 4 товаров: указать ID Digiseller, адрес, тексты (ограничения, получение, инструкция), изображения, «Показан».
   Название, цена, наличие и варианты по умолчанию берутся из Digiseller — ничего не выдумывается.
4. В кабинете Digiseller: URL уведомления о продаже → `BASE_URL/api/digiseller/notify`, URL возврата → `BASE_URL/order/return`.
5. Положить документы в `config/pages/{rules,offer,privacy}.html`, вопросы — в `config/faq.json` (`[{"q":"…","a":"…"}]`).
6. «Обновить отзывы и статистику» в админке (далее автоматически раз в 6 часов; вручную — `npm run sync`).

## Что нужно проверить на аккаунте владельца
Digiseller-хосты из этой среды были недоступны, поэтому формат ответов API реализован по документации и разбирается защитно
(неизвестный ответ = ошибка, а не «0»/успех). При подключении проверить: поля `/api/products/{id}/data`, правила модификаторов
вариантов (`modify_type`), параметры страницы оплаты (`DIGISELLER_PAY_URL`), поля уведомления о продаже, ответ `unique-code`.
Пункт S.9.13 (реальная контрольная покупка) выполняется вручную.
